### Descriptor literature and library facts gathered for the proposal

- **Chemprop 2.3.1 mechanics** [assistant, source read]: `MPNN.fingerprint` returns the batch-normalized aggregated vector concatenated with `X_d_transform(X_d)`. [web: Chemprop docs, two pages read] the FFN `input_dim` is message-passing output dim plus the number of `X_d` columns; scaling `X_d` is recommended and done by fitting a `StandardScaler` on the training set (`normalize_inputs("X_d")`), applying it to validation, and passing `ScaleTransform.from_standard_scaler(...)` to the MPNN; the pages say nothing about NaN or inf descriptors and nothing about pre-normalized RDKit descriptors. ### Proposed comparison (needs Miles's approval and a D-record; no implementation or training before then)

**Arms.** R = updated T121 (existing 150 cells, O150 0.6769540372619428, unchanged). D = updated T121 plus molecule-level descriptors.

**Preserved:** the D007 split manifests (150 cells, 50 partitions × 3 seeds, paired cell by cell), trial 121's `sampled_config` (not retuned), CI-based observation weighting in training (D015 item 5, D016: evaluation unweighted), screening schedule (50 epochs, warmup 10) and checkpoint-selection rule, the transfer rule, training-only target scaling, the existing fit horizon and callbacks, the frozen scorer, development-only data, protected sets untouched.

**Changed:** a molecule-level descriptor vector enters at the readout (concatenated to the aggregated vector), so the first FFN layer's input grows from 600 to 600 plus the descriptor count.

**Design question that decides what "preserving the recipe" means.** Updated T121 transfers the screening model's first FFN layer. Adding descriptors changes that layer's input shape, so:
- **Design A (chosen by Miles 2026-11-19, §2 item 8): descriptors in both stages.** New screening run with descriptors (same schedule and selection rule), then 150 cells. Transfer stays intact, so R and D differ only by the descriptor input; the cost is one new screening run and a new 150-cell array (graph-only precedent: cells 1:40 to 2:33 each; screening runtime UNKNOWN).
- **Design B: descriptors only in the pIC50 stage.** Transfer message passing and aggregation only; the first FFN layer is fresh. This confounds descriptors with the loss of FFN transfer and would need an extra control arm (updated T121 with a fresh first FFN layer) to attribute any change. Not recommended as primary.

**Descriptor set (recommendation, with reasons).** The RDKit 2D set (Chemprop 2.3.1 `v1_rdkit_2d_normalized`, 200 columns) **minus the four partial-charge columns at positions 39, 41, 43, 45, i.e. 196 descriptors** (the drop is decided, §2 item 7; the rest of this paragraph is the proposal), single primary arm:
- same 200-feature class as Yang 2019, the standard D-MPNN descriptor addition, with the caveat that its effect is dataset-dependent (helped low-data and some regression sets, hurt PCBA and HIV), so a gain is not presumed;
- finite for all 4,169 development compounds in a local check, but **not for four screening-only metal-containing molecules** (Au, Fe, Bi; four partial-charge columns each; see the feasibility bullet in §4), so a handling rule is needed before the screening stage can use it;
- computed deterministically from SMILES without labels, so it cannot leak labels, and needs no external pretrained model;
- consistent with PXR D018's choice (PXR code reuse proposed, not decided).
Evaluated and parked: a small physicochemical set (interpretable, but no CYP-specific evidence gathered here; Yang suggests task-relevant features); Mordred (about 1.6k features, heavy, more non-finite risk; also the territory of CheMeleon-style pretraining); Morgan count fingerprints as `X_d` (the project baseline's own representation; not a "descriptor" in the sense Miles named); atom or bond level features (out of the molecule-level scope).

**Scaling (recommendation).** Use the fixed normalized descriptors (bounded in [0, 1], no learned parameters, so no per-cell scaler and no mismatch between the screening-stage and pIC50-stage inputs to the transferred layer), with an identity `X_d_transform`. Reason: a learned `StandardScaler` per cell would give the transferred first layer inputs scaled differently from the screening stage, and Chemprop itself warns that `StandardScaler` suits RDKit 2D features poorly. This departs from the Chemprop docs' default recommendation to fit a training-set `StandardScaler`; the normalized values are already of order one, which is the reason the docs give for scaling.
